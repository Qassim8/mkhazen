# تحديث 2026-10-13 — خطوات التطبيق

## 1) قاعدة البيانات (Supabase → SQL Editor)
1. خذ نسخة احتياطية (`pg_dump`) كالمعتاد.
2. شغّل الملف: `database/migrations/20261013_01_tailor_dues_and_deposit.sql`
   (يمكن إعادة تشغيله بأمان).
3. شغّل بعده: `database/migrations/20261010_06_reassert_api_acl.sql`
4. (اختياري) شغّل `database/migrations/20261010_verify.sql`، ويجب أن تكون كل النتائج PASS.

## 2) الكود
1. فك الـ zip في جذر المشروع، مع استبدال الملفات الموجودة.
2. **احذف** الملف التالي، لأن الدفع للخياط من صفحة الطلب أُلغي:
   `app/api/tailoring/commission-payments/route.ts`
3. `npm install`، لتثبيت مكتبة `@zxing/browser` البديلة لمسح الباركود.
4. `npm run build` ثم أعد التشغيل.

## 3) ملاحظات
- **مسح الباركود بالكاميرا** يعمل على HTTPS فقط. تم السماح بالكاميرا في
  `Permissions-Policy` لنفس الموقع فقط (`camera=(self)`).
- **سداد مستحقات الخياط أو السلفة** يتم من: المحاسبة ← مستحقات الخياطين.
  تُوزَّع الدفعة على الطلبات من الأقدم للأحدث، ويُسجَّل لكل طلب سطر قيد بنفس المرجع
  (`TLR-DUES-…` للسداد و`TLR-LOAN-…` للسلفة)، حتى تبقى تسوية فروق الصرف لكل طلب صحيحة.
- **الدوال القديمة** `pay_tailor_payment` و`pay_tailor_commission` بقيت في القاعدة كما هي،
  ولم يعد التطبيق يستدعيهما.
